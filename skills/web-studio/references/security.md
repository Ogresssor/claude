# Безопасность — обязательный чек-лист

Если задача требует ослабить защиту (отключить проверку, открыть доступ), сначала предупреди о риске и предложи безопасную альтернативу.

## Секреты
- Никогда не коммить ключи, токены, пароли. Только `.env.local`; в репо — `.env.example` с пустыми значениями.
- `.gitignore` с самого начала: `.env*` (кроме `.env.example`), `node_modules`, `.next`, `.vercel`.
- `NEXT_PUBLIC_*` попадает в браузер — туда только публичные значения.
- Утёкший секрет считается скомпрометированным: отозвать и перевыпустить, а не только удалить из истории.

## Ввод и данные
- Валидация любого ввода **на сервере** (zod), даже если есть клиентская.
- Без `dangerouslySetInnerHTML` с пользовательскими данными; если нужен HTML — DOMPurify.
- SQL — только параметризованные запросы или ORM.
- Загрузка файлов: проверка типа и размера, хранение вне публичной папки или в объектном хранилище.

## Авторизация
- Проверка прав на сервере в каждом Server Action и Route Handler, а не скрытием кнопки.
- Supabase: RLS включён на всех таблицах, `service_role` только на сервере.
- Cookies сессии: `HttpOnly`, `Secure`, `SameSite=Lax`/`Strict`.
- Rate limiting на логин, формы и API; защита форм от спама (honeypot / Turnstile).

## Заголовки и инфраструктура
- `Content-Security-Policy`, `Strict-Transport-Security`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`, `frame-ancestors`.
- Только HTTPS; `target="_blank"` — с `rel="noopener noreferrer"`.
- Ошибки пользователю — без стектрейсов и внутренних деталей.

## Зависимости
- `npm audit` / `pnpm audit`, lock-файл в репо.
- Не ставить сомнительные пакеты, следить за опечатками в названиях (typosquatting).
- Dependabot / Renovate и GitHub secret scanning.

## Пути, которые всегда показывать пользователю на подтверждение
Авторизация, платежи и биллинг, CI/CD-воркфлоу, деплой и релизные скрипты, миграции БД, установщики.
